# 日志规范

本规范定义 Blessing Galgame Engine 的日志格式、级别语义、模块标签与消息文案约定。所有运行时代码的日志输出必须遵守本规范。规范本身的修改需通过 PR 评审。

## 1. 消息格式

所有级别的日志共用唯一格式：

```
[2026-09-14 00:06:26.318] [INFO ] [StoryManager] 加载剧本: demo_scene1 (25 项)
```

| 字段 | 格式 | 说明 |
| --- | --- | --- |
| 时间戳 | `YYYY-MM-DD hh:mm:ss.mmm` | 本地时间，毫秒精度 |
| 级别 | 定宽 5 字符：`DEBUG` / `INFO ` / `WARN ` / `ERROR` | 符号化字段，不用中文 |
| 模块标签 | `[TagName]` | 见第 3 节 |
| 消息 | 自由文本 | 见第 4 节 |

输出行为：

- 控制台按**级别**着色：DEBUG 灰、INFO 白、WARN 黄、ERROR 红；
- `WARN` / `ERROR` 同时经 `push_warning` / `push_error` 进入 Godot 调试器（编辑器内可定位真实调用点）；
- 日志文件输出同一格式的纯文本（不含颜色标记）。

## 2. 级别语义

| 级别 | 语义 | 判定问题 | 示例 |
| --- | --- | --- | --- |
| DEBUG | 内部状态、逐对象细节，默认关闭 | 关掉它功能排查是否仍可能？ | `资源无变化: scripts/demo/scene1.txt` |
| INFO | 关键生命周期事件，必须稀疏 | 用户/维护者是否需要知道这件事发生了？ | `导入完成: 更新 2 个剧本` |
| WARN | 可恢复异常，兜底已生效 | 功能是否继续且结果基本正确？ | `模组目录不存在，跳过模组加载` |
| ERROR | 功能失败、资源缺失，需要人介入 | 是否有用户可见的错误后果？ | `加载背景失败: demo_stage` |

常见误用红线：

- 循环内、逐文件、逐资源的"尝试/成功"消息一律 DEBUG，不得占用 INFO；
- 能自动恢复的降级（回退默认值、跳过可选功能）是 WARN，不是 ERROR；
- ERROR 意味着"有人需要修东西"，不用于预期内的分支。

## 3. 模块标签（LOG_TAG）

### 3.1 规则

1. 每个含日志调用的脚本文件，在文件顶部（`extends` 行之后）定义：
   ```gdscript
   const LOG_TAG := "StoryManager"
   ```
   文件内所有日志调用第一个参数一律传 `LOG_TAG`；
2. 标签名 = **子系统名**（通常是主类名），不是文件名；
3. **文件移动、改名、重构内部结构时，标签不变**——标签跟随职责，不跟随物理位置；
4. 只有当一个文件的职责分裂成两个子系统时才新增标签；新标签必须先登记到本文件第 7 节的注册表，再使用；
5. 标签用 PascalCase 英文（与类名一致），它是结构字段，不是消息正文。

### 3.2 为什么不用调用栈推断

（本项目曾因此产生实际缺陷：多参数 API 族的帧深度不同，导致来源全部误报为 logger 内部。）调用栈推断把"公开 API 与取栈点之间隔几帧"作为隐式契约，任何包装层都会使其静默指错；且日志需要的是稳定的子系统名，不是易变的物理文件位置。显式常量还有全文可检索的附加价值。

## 4. 消息文案

- 正文一律**中文**，现在时，无句尾标点；
- 句式：`动作: 对象` 或 `动作 结果: 对象`；
- 上下文数据用 key 化拼接或 `%` 格式化，key 用英文小写：
  ```gdscript
  GalLogger.info(LOG_TAG, "加载剧本: %s (%d 项)" % [script_name, count])
  GalLogger.error(LOG_TAG, "存档写入失败: path=%s" % path)
  ```
- 不再使用多参数拼接 API（`infos/warns/infot` 等已废除）；
- 不打印大段数据（整个数组/字典）：只打尺寸与关键字段。

## 5. API

`GalLogger` 只保留四个方法：

```gdscript
GalLogger.debug(tag, msg) / .info(tag, msg) / .warn(tag, msg) / .error(tag, msg)
```

- 业务代码禁止裸 `print()` / `printerr()` / `push_warning()` / `push_error()`；
- 例外：`test/` 下的命令行测试脚本（如 `test/smoke_test.gd`），其 `print` 是测试输出而非日志。

## 6. 配置与性能

- `config.json` 的 `logger.level`（`DEBUG/INFO/WARN/ERROR`，默认 INFO）与 `logger.file`（留空则不写文件）；
- 热路径（逐帧、逐事件循环）只许用 DEBUG；注意 GDScript 会先行求值参数字符串，昂贵拼接需自行用 `if` 守护；
- 明确不做：JSON 结构化日志、日志轮转、远程上报。项目规模需要时再议。
