# 可视化编辑器与编译管线设计

面向编剧的 Web 可视化剧本编辑器，及其依赖的 Godot 无头编译 CLI。本文是
`docs/未来开发设计.md` 阶段三「导入器和开发工具链」中**剧本检查命令**与
**Web 可视化剧本编辑器**两项的完整落地设计。

## 目标与范围

- 编剧在浏览器中以节点图方式编写 BGalS 剧本，不接触文本语法细节也能产出合法剧本。
- 程序与引擎侧零新运行时负担：编辑器产物是 `scripts/` 下的 `.txt`，走既有哈希增量编译管线。
- 图与文双向转换、互为校验：「图 → 文 → 编译产物 → 图」必须语义守恒。
- 本设计覆盖两件套：**编译 CLI**（check / compile / dump / spec）与**编辑器全流程**
（工程模型、编辑、校验、导出、导入、版本同步）。引擎运行时本身不改语义。

## 设计原则

1. **文本是引擎唯一事实源**。`scripts/*.txt` 进版本库、被编译、被运行时消费；
   编辑器自己的工程文件（布局、注释节点）是 sidecar，引擎永远不读。
2. **产物做桥，不做文本回读**。反向（文 → 图）不发明文本解析器，复用编译产物
   `GalSs/*.tres`——它的结构近乎完整（类型化参数、条件 RPN、选项组回填字段），
   只丢注释与书写习惯（见「已知信息损耗」）。
3. **职责单向拆分，零重复实现**：
   - GDScript 侧：解析（txt → seq）与转储（seq → 图 JSON）。永远不发射文本。
   - TypeScript 侧：发射（图 → txt）与图编辑。永远不解析文本。
4. **前端零硬编码**：指令名表、参数规格、语义角色、条件记号全部由 CLI 的
   `spec` 输出提供；指令集演进时前端无需改代码。
5. **CLI 即测试面**：CLI 的三个子命令全部可在 CI 无头运行，golden 文件回归。
6. **版本纪律**：本设计不含任何序列化格式变更，`COMPILER_VERSION` 不动；
   图 JSON 自带独立 `format` 版本号，与编译器盐解耦。

## 总体架构

```
                ┌──────────────────────────────────────┐
                │  Web 编辑器（React + React Flow）      │
                │  内存图模型 ⇄ sidecar(.graph.json)     │
                └───┬──────────────▲──────────┬─────────┘
        emit 图→文  │              │ 图 JSON   │ check 诊断
                    ▼              │          │
scripts/*.txt ── compile ──▶ GalSs/*.tres ── dump ──────┘
    │                  │                │
    │            .hash 增量          compiler 版本校验
    │            + 版本盐               │
    │                                  ▼
    └──────── 运行时 ResourceManager.load("script", …)
```

三条通道，全部经 `tool/bgals_cli.gd` 无头执行：

| 通道 | 方向 | 用途 |
|---|---|---|
| check | txt → 诊断 JSON | 编辑器实时校验；CI 门禁 |
| compile | txt → tres | 与编辑器内 F5 等价的批量编译（复用同一管线） |
| dump | tres → 图 JSON | 导入既有剧本；回环校验 |
| spec | ∅ → 规格 JSON | 编辑器启动时取指令名表与参数规格 |

## 编译流程

### 现状管线（基线，不变）

- 触发：`ResourceManager._ready` 在编辑器模式且 `config.scripts.check=true` 时
  创建 `DialogueImporter` 节点编译全部剧本，导出构建跳过
  （`resource_manager.gd:28-40`）。
- 编译：`import_dialogues(read_dir)` 扫描源目录生成 `known_scripts`
  （相对路径去扩展名、分隔符换下划线），逐文件 `import_dialogue` →
  静态 `parse_script(lines, file_name, diags, known_scripts, char_max, known_refs)`
  产出 `GalEventItemSequence{compiler, seq}`（`dialogue_importer.gd:65-115, 171`）。
- 增量：`GalSs/.hash` 记录 `{_compiler, <txt 路径>: sha256}`；哈希或版本盐不符才重编
  （`dialogue_importer.gd:45-60, 96-101`）。有 error 的文件跳过保存。
- 产物校验：`ResourceManager.load("script", …)` 比对 `compiler` 标记，陈旧产物拒载
  （`resource_manager.gd:82-87`）。
- 注入：`char_max` 来自 `config.json character.max`；`known_refs` 即
  `ResourceManager._path_dict`（index.json 三域登记表 + 产物目录扫描的 script 域）。

### CLI：`tool/bgals_cli.gd`

单入口、子命令分发，`extends SceneTree`（与 `test/executor_test.gd` 同形态）：

```bash
godot --headless --path . -s tool/bgals_cli.gd -- check   --src <文件|目录> --out report.json
godot --headless --path . -s tool/bgals_cli.gd -- compile --src <目录> [--report report.json]
godot --headless --path . -s tool/bgals_cli.gd -- dump    --src GalSs/demo_scene1.tres --out graph.json
godot --headless --path . -s tool/bgals_cli.gd -- spec    --out spec.json
```

- 启动后 `call_deferred` + 等两帧，autoload 就绪（`-s` 模式下 autoload 照常加载，
  经 `root.get_node("ResourceManager")` Variant 动态访问取注入值，复用生产路径、
  零复制装配逻辑）。
- JSON 一律**写文件**（`--out` 指定），stdout 只打一行状态（如
  `BGALS_CLI_DONE ok=true errors=0 warnings=2`）——规避 Windows 控制台编码与
  大 JSON 截断问题。
- 退出码：`0` 成功；`1` 诊断含 error；`2` 用法/IO 错误；`3` 产物 compiler
  版本不匹配（dump 专有，提示编辑器重新同步版本）。

### 引擎侧配套小改动（M0 一并做，均为新增/薄壳，无格式变更）

1. `DialogueImporter` 抽两个静态方法，实例方法变薄壳：
   - `static scan_script_names(read_dir) -> Array[String]`（现 `:73-75` 的内联逻辑）；
   - `static compile_file(text_path, output_path, known_scripts, char_max, known_refs) -> Array[Dictionary]`
     （现 `import_dialogue` 的解析+诊断+落盘主体，返回 diags）。
2. `ResourceManager` 加公开访问器 `get_known_refs() -> Dictionary`（`_path_dict` 快照），
   供 CLI 注入，避免外部触碰下划线字段。
3. `Instruction` 加 `const _STRUCTURAL_PARAMS: Dictionary`
   （结构回填字段索引表，紧邻 `_SPEC` 维护，见下节）。
4. 新增 `Autoloads/graph_dumper.gd`（`class_name GraphDumper`，纯静态、不引用 autoload）：
   seq → 图 JSON 的全部逻辑，CLI 与测试共用。
5. 新增 `tool/bgals_cli.gd`（无 class_name，仅入口）。

### 各子命令语义

- **check**：对 `--src` 每个文件读入行数组 → `parse_script`（注入齐备）→ 汇总 diags，
  不写任何产物。report：`{ok, files, diags:[{file,line,level,msg}], stats}`。
- **compile**：对目录逐文件 `compile_file`（与编辑器内编译同一函数），更新 `.hash`；
  report 同 check 附加 `outputs`。
- **dump**：`ResourceLoader.load(tres)` → 校验 `compiler`（不符退 3）→
  `GraphDumper.build(seq, script_name)` → 图 JSON。
- **spec**：输出指令名表与规格（见「spec 输出」），不依赖任何输入文件。

## 图数据模型（dump Schema）

### 顶层结构

```json
{
  "format": "bgals-graph/1",
  "compiler": "bgals2.4",
  "script": "demo_scene1",
  "nodes": [ ... ],
  "edges": [ ... ]
}
```

- `compiler` 与产物一致，编辑器据此判断兼容性。
- 节点 id 稳定生成（`n<seq 下标>`），供 sidecar 布局对照；内容匹配见「导入」节。

### 节点 / 边对照表

| BGalS 构造 | 节点 kind | 承载方式 |
|---|---|---|
| 对话行 | `dialogue` | `character` + `text`（锚点、插值原样保留原文）+ `anchors` 提取数组；前/后指令为 `prev`/`post` 插槽（各为指令对象数组） |
| 独立指令 | `inst` | `head`（指令名字符串）+ `params`（**按名**的对象，默认值省略） |
| 选项组 | `option_group` | 每条出边 `kind:"option"`，边上带 `text` 与 `cond`（中缀或 null）；体是子图，汇合于组后 |
| if/elif/else 链 | `cond` | 每条出边 `kind:"branch"`，边上带 `cond`（else 为 null）；体是子图，汇合于 END_IF 后 |
| jump | `jump`（终端节点） | `target` = 脚本名或 `main_menu` |
| begin | `inst`（head=SET_BEGIN_SCRIPT） | 普通指令，无特殊结构 |
| 注释 | `comment` | **dump 不产生**；仅存于 sidecar 与导出 txt |
| 起止 | `start` / `end` | dump 合成，无对应源构造 |

边 kind：`seq`（顺序流）、`option`、`branch`、`jump`（跨剧本，虚边，仅可视化）。

### 结构回填字段的消解

编译期回填字段（`Instruction._SPEC` 中的 `OPTION[2..5]`=is_head/body_start/next_option/
group_end、`IF[1]`、`ELSE_IF[1..2]`、`ELSE[0]`，及 `OPTION_END`/`END_IF` 整条）是
**跳转表，不是语义**。dump 把它们消费为图结构（分组、边、汇合），不出现在节点参数里；
编辑器导出文本时按缩进块重写，编译器重新回填。知识落点：`Instruction._STRUCTURAL_PARAMS`
常量（`{Head.OPTION: [2,3,4,5], Head.IF: [1], …}`），spec 输出中对应参数标
`"structural": true`，前端表单自动隐藏。

### 条件 RPN → 中缀

产物中条件为后缀记号流 `[[CondTag, payload], …]`（`instruction.gd:69-78`）。
dump 用标准栈式逆解析回中缀字符串，优先级 `比较 > not > and > or`，
子表达式优先级不足时补括号。编辑器内条件始终是中缀文本（图 → 文方向由编译器
重新生成 RPN），编辑器永不需要构造 RPN。

### 锚点与对话正文

对话正文在图模型中就是 BGalS 原文（`[sfx rain]`、`{affection}` 原样保留），
编辑器提供高亮与校验，不做二次封装。dump 额外用 `DialogueRenderer.render(raw, {})`
提取 `anchors:[{index, head, params}]` 供前端高亮定位（`index` 以剥离后显示文本为基准，
`dialogue_renderer.gd:9-14`）。导出时正文逐字写回，仅应用两条确定规则：

1. 行首是保留字符（保留字、`*`、`>`、`<`、`#`、`/`）→ 行前补 `\`；
2. 文本中的 `\` 自身按渲染器转义规则补全（`\` → `\\`，孤立的 `[`/`{` 按需转义）。

### spec 输出（前端零硬编码）

`spec.json`：

```json
{
  "compiler": "bgals2.4",
  "heads": ["BLANK", "MUSIC_PLAY", ...],
  "spec": {"MUSIC_PLAY": [{"name":"path","type":"STR","default":"","role":"audio","structural":false}, ...]},
  "cond_tags": ["PUSH_NUM","PUSH_VAR","CMP","NOT","AND","OR"],
  "anchor_whitelist": ["sfx","voice","char","bg","music","trans","pause"],
  "reserved_keys": ["bg","music","sfx","voice","char","var","if","elif","else","jump","begin","wait","scene","trans"],
  "indent_unit": 4
}
```

数据来源：`Instruction.Head.keys()`、`Instruction._SPEC`、`_STRUCTURAL_PARAMS`、
`DialogueImporter.ANCHOR_WHITELIST`/`RESERVED_KEYS`。编辑器启动时取一次并按
`compiler` 缓存；指令集演进只改引擎，前端表单、校验、高亮自动跟随。

### 已知信息损耗（反向）

| 损耗 | 对策 |
|---|---|
| 注释与空行（编译即丢弃） | 编辑器设 `comment` 节点，存 sidecar，导出时写 `#` 行 |
| 书写习惯（如 `fade:2` 糖写法） | dump 已按 spec 拆成显式字段；再导出统一显式写法，语义不变 |
| 编译失败的中间态 | 进不了图（无产物）；靠编辑器实时 check 兜底 |
| 模组包（`scripts.check=false`） | 无产物可回读，不进编辑器（边界，见末节） |

## 编辑器流程

### 形态与技术选型

- **Web 前端**：Vite + React + TypeScript + React Flow（自定义节点/受控状态成熟，
  生态与 vibe 开发友好）；导入自动布局用 dagre。
- **本地伴随服务**：Node 20 + fastify，工作目录指向游戏项目根。职责：
  读写 `scripts/` 与 sidecar、spawn CLI 三子命令、读 `index.json`（资源下拉数据源）。
  纯文件与进程桥，无业务逻辑。后期可用 Tauri 打包为单窗口应用，前端零改动。
- 非目标平台约束：Godot 无头启动约 1-3s，check 走「保存时触发 + 500ms 防抖」；
  若实测不可接受，CLI 再加 `--serve`（stdin JSONL 常驻模式）——属优化项，不进 M0 承诺。

### 工程文件与事实源

- 事实源：`scripts/<路径>.txt`（进版本库，引擎消费）。
- sidecar：`scripts/<路径>.graph.json`（进版本库，引擎不读）：
  `{format:"bgals-editor/1", compiler, script, layout:{nodeId:{x,y}}, comments:[…]}`。
- 打开流程：companion 先跑增量 compile（哈希保证廉价）→ dump 得图 →
  sidecar 叠加布局与注释节点。节点身份用**内容哈希匹配**（kind+head+文本摘要），
  匹配失败的区域自动布局兜底；外部改动（git pull 来的手改 txt）由此自然并入。

### 导出（图 → 文）

- 从 `start` 沿 `seq` 边拓扑走查；选项组/条件块的体按 4 空格缩进内联展开。
- 指令行按 spec 参数序规范发射：`head 位置参数 key:值 …`，仅写非默认值。
- 条件、选项条件为中缀原文；对话正文应用上节两条转义规则。
- `comment` 节点原位写 `#` 行；段落间空行按编辑器的分块间距生成。

### 导入（产物 → 图）

- 打开无 sidecar 的剧本：compile → dump → dagre 自动布局 → 生成 sidecar。
- 手写注释在首次导入时丢失（编译期已丢弃），属一次性成本，导入结果页明示；
  此后注释由 sidecar 保管，导出回写 txt，不再丢。

### 互为校验回路

编辑器内置「回环校验」：当前图 → emit txt → compile → dump → 与内存图做语义投影对比
（剔除 id、布局、注释）。一致即图文互译无损；不一致逐节点列出差异。
同一回路进编辑器仓库 CI（TS 发射器 + 无头 Godot），固定夹具覆盖 demo 三剧本
（选项、条件、锚点、音频指令齐备）。

### 实时诊断

保存 → 写 txt+sidecar → companion 跑 check → 诊断按 `file:line` 映射回节点
（dump 节点带 `line` 字段；导出时同步维护行号表）→ 画布红/黄角标 + 诊断面板点击跳转。
规则与编译期完全一致（同一 `parse_script`），不存在「编辑器里合法、引擎里报错」。

### 编剧端到端工作流

1. 启动 companion（指向项目根），浏览器打开编辑器。
2. 新建/打开剧本；左栏剧本列表 + 诊断，中栏画布，右栏属性面板
   （spec 驱动的表单：参数类型控件、index.json 资源下拉、条件中缀编辑器）。
3. 拖拽编辑：对话块（前后指令插槽）、指令节点、选项组、条件分支、注释节点。
4. 保存 → 自动校验，诊断即见即改。
5. 回环校验通过后提交：`txt + graph.json` 进 git；引擎 CI 三套件照常。
6. 引擎侧 F5 即玩（现状增量编译管线不变）。

## 版本绑定与发布同步

- 图 JSON 与 spec JSON 都带 `compiler` 字段；编辑器内置兼容编译器列表，
  不匹配时横幅提示并只读。
- 引擎指令集演进（_SPEC/Head 尾部追加）不必然动 `COMPILER_VERSION`（那是序列化盐）；
  但编辑器以 spec 输出为准，天然跟随。若序列化格式变更导致盐升级，旧 tres 的 dump
  退 3，编辑器提示重新 compile。
- 编辑器仓库 CI 钉住引擎 commit 跑回环夹具；兼容矩阵写编辑器 README。

## 测试策略

- **引擎侧**（本仓 CI 新增 `cli_test.gd`，与 diagnostics_test 同形态）：
  `scan_script_names`/`compile_file`/`GraphDumper.build` 纯静态单测；
  demo 三剧本 dump golden 对比（语义投影，剔除 id）；
  spec 输出与 `_SPEC` 一致性自校验；错误产物版本退 3。
- **编辑器侧**（编辑器仓 CI）：emit 器单测（转义、缩进、默认值省略）；
  回环夹具（图 → 文 → 编译 → dump → 对比）；诊断映射组件测试。
- 职责边界遵守「GDScript 不发射、TS 不解析」，两侧测试面不重叠。

## 风险与对策

| 风险 | 对策 |
|---|---|
| 无头启动延迟影响校验体验 | 防抖 + 保存时触发；必要时加 `--serve` 常驻模式（优化项） |
| Windows 控制台编码/大 JSON | JSON 全走文件，stdout 只打状态行 |
| 节点 id 漂移破坏布局 | 内容哈希匹配 + 区域自动布局兜底 |
| tres 版本盐绑定 | dump 退 3 + 编辑器兼容矩阵 + 提示重编译 |
| 大剧本图性能 | 一剧本一图；跨剧本 jump 用虚边节点而非全量展开 |
| 手写注释首导丢失 | 导入结果页明示；后续由 sidecar 兜底 |

## 边界（不做的事）

- 不做运行时可视化调试、不断点单步（属引擎调试器范畴）。
